# API Task 34 — Contract, Authentication, Errors: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the security boundary and wire contract of the API: `views.py` (the whole read model), `errors.py`, `deps.py`, `auth.py`, `main.py`, the `api-is-read-side` import contract and the `create-operator` command. No resource route exists after this task.

**Architecture:** FastAPI app factory `create_app(settings=)` mounting `/api/v1/auth/*` only. Sessions are random 32-byte cookies stored as SHA-256 in `sessions`; passwords are argon2id; the login throttle is counted in `audit_log`; every non-GET must carry the configured web `Origin`; every error is RFC 9457 `problem+json` that never echoes input. Read-only by construction: an import-linter contract forbids every module that can start, resolve or write a run.

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, `argon2-cffi`, `import-linter`, `pytest`, `mypy --strict`, `ruff`.

**Spec:** [`docs/superpowers/specs/2026-09-26-selector-drift-api-contract.md`](../specs/2026-09-26-selector-drift-api-contract.md), §1–§5 and **§10 (addendum 2026-10-19, which wins on any conflict)**. Sibling plan tasks 34B (`derive.py`) and 34C (routers, evidence, types) follow as separate cycles and are **out of scope here**.
